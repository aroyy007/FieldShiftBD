## Access, licensing, and freshness controls

- Direct robots.txt and sitemap.xml requests for the inspected BARC/CropZoning, BAMIS, SRDI, and Crop Intelligence hosts were not accessible through the research browser. This is inconclusive; it does **not** establish that crawling is allowed or disallowed. Check robots/terms from the deployment network before scheduling a fetch.
- BARC's linked [maps catalogue](https://apps.barc.gov.bd/maps/) and [Land Resource Information Management System](https://apps.barc.gov.bd/lri/) require signup/login for map/data downloads. Their public pages disclose CC BY 4.0 for downloads unless otherwise noted, while the LRI page also says commercial use is strictly prohibited. These terms need dataset-specific review; no gated data was accessed.
- No reviewed source documented a general-purpose public agronomic API. Use official downloadable/publications for versioned references, and live fetch only for explicitly current advisories/forecasts with issue/expiry metadata. Keep source URL, publisher, region/crop, publication or issue date, valid-through date, language, and license with every knowledge item.
- This review summarizes source surfaces and metadata; it does not claim agronomic validation of individual recommendations. For fertilizer or crop-disease advice, preserve the source's scope and advise expert/extension confirmation where the source itself requires it.

## Scraping decision

No automated whole-site scrape is included in this change. The reviewed sites expose public static publications alongside client-rendered GIS, location/year-filtered tables, and expiring bulletins; the inspected pages did not document a general-purpose API or shared freshness schema. Scraping rendered map pages would not establish the underlying layer's year, spatial unit, calculation assumptions, reuse rights, or whether a forecast is still valid. For those data, first request a documented BARC/SRDI export or an authorized BAMIS/BMD/FFWC feed.

If an approved fetcher is later needed, I recommend a small, source-specific [Scrapy](https://github.com/scrapy/scrapy) spider for repeatable, structured HTML/document extraction, adding [scrapy-playwright](https://github.com/scrapy-plugins/scrapy-playwright) only for a page that genuinely requires JavaScript rendering. Both projects are free and open source; `scrapy-playwright` documents Python 3.10+, Scrapy 2.7+, and Playwright 1.40+ requirements. [Crawl4AI](https://github.com/unclecode/crawl4ai) is another free option for JavaScript-heavy pages and Markdown extraction. Given this app's need to keep crop, region, units, source year, and validity as typed fields with provenance, I infer Scrapy's structured item pipeline is the better authoritative ingestion path than LLM-oriented Markdown extraction.

Any future crawler should check site terms and robots policies from the deployment network first, set Scrapy's `ROBOTSTXT_OBEY=True`, use low per-domain concurrency and a delay, retain the original document/URL and retrieval timestamp, and require review before import. The research browser could not verify the sites' robots.txt or sitemap.xml responses, so permission to crawl remains unconfirmed. Do not access authenticated app content, bypass controls, or scrape map tiles as a substitute for an official data export.

## Starter data and import

The companion [`agricultural_knowledge_seed.json`](../app/data/agricultural_knowledge_seed.json) contains five source-grounding notes based on BARC, BAMIS, and SRDI. They are intentionally marked `in_review`, have no crop foreign key, and do not contain pesticide instructions, crop calendars, or numeric fertilizer rates. The seed is not an exhaustive crop knowledge corpus; crop-level guidance should be added as versioned, location-aware entries after the original source and its conditions are checked.

The importer [`import_agricultural_knowledge.py`](../scripts/import_agricultural_knowledge.py) writes records to the existing `agricultural_knowledge` table with stable IDs. It does not delete records absent from the seed. If a seeded source record changes, it returns that row to `in_review` and clears its reviewer fields. Only a qualified reviewer should approve records for farmer-facing advice. Run it from the `backend` directory after the database migration has been applied:

```bash
python -m scripts.import_agricultural_knowledge --check-only
python -m scripts.import_agricultural_knowledge
```

With Docker Compose, run the same commands in the backend container. `--check-only` validates the data file without opening a database connection.
