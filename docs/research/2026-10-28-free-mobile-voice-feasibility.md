# Free mobile voice feasibility — 2026-10-28

Scope: review of `docs/plans/2026-10-06-voice-first-bangla.md`; research only, no implementation or alteration of the plan. Official sources checked on 2026-10-28. Free tier terms can change.

## Decision

An Android APK with tap-to-talk Bangla input, system speech output, bundled human prompts, confirmation before writes, and text/tap fallback is technically feasible with no purchased voice API. A limited demo or pilot can have zero additional hosting spend while it fits free allowances or uses existing team hardware. **An indefinitely available production service with durable database, uploads, inference, backups, monitoring and unlimited users cannot honestly be guaranteed at zero cost.** Free software licenses and no API fee do not provide free server capacity or availability guarantees.

Recommended scope: implement the plan's Android Tier 0, but prioritize one complete farmer decision loop over widgets, every command, a large recording library, or server speech models. Keep iOS and self-hosted neural voice as later deliverables. State measured device and farmer results rather than universal language/accuracy claims.

## Speech implementation and corrections

- Android `SpeechRecognizer` supports querying availability and creating an on-device recognizer, but that recognizer must actually be available on the device. The platform warns that implementations may stream audio to remote servers and are not intended for continuous recognition. There is no universal Bangla offline guarantee. [Android API](https://developer.android.com/reference/android/speech/SpeechRecognizer)
- `expo-speech-recognition` currently documents Expo SDK 57 support, its config plugin, and a required development build. This is compatible in principle with the project's SDK 57/RN 0.86 dependencies. Native voice testing must use an actual Android build; a successful Chrome test does not establish native permission, lifecycle, speech-engine, or offline behavior. [Maintainer README](https://github.com/jamsch/expo-speech-recognition), [Expo local development](https://docs.expo.dev/guides/local-app-development/)
- Important correction to the plan: `getSupportedLocales()` is **not supported on Android 12 and below**. Android 10–12 need an availability/attempt/error fallback, rather than an unconditional locale query. On newer phones, distinguish supported locales from downloaded offline locales and handle model download failure. The library describes on-device model downloads on Android 13+. [Maintainer API documentation](https://github.com/jamsch/expo-speech-recognition#getsupportedlocales)
- Use `expo-speech` and enumerate available voices; select an installed `bn-BD` or `bn-IN` voice only after checking. Missing voices need a clear fallback. iOS physical devices may be silent when the silent switch is enabled. Do not confuse Bengali keyboard/VoiceOver availability with guaranteed recognition of `bn-BD`; query supported locales and test the intended OS/device. [Expo Speech](https://docs.expo.dev/versions/latest/sdk/speech/), [Apple recognizer capability](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition)
- Keep tap-to-talk foreground-only. Add cancel, permission denial, timeout, silence, network failure, recognizer busy, and speaking/listening overlap behavior. Native lifecycle checks are required to ensure the microphone stops when backgrounded.
- The plan's blanket rejection of all tiny/base/small Whisper models based on a single anecdote is not a scientific model-selection result. Evaluate specific checkpoints on local Bangla samples, numbers, crop names and regional speech. Conversely, do not ship a larger model merely because a model card says Bengali is supported.

## Model and service licensing

- Meta MMS TTS is CC-BY-NC-4.0; it is unsuitable for a commercial-ready stack under this plan's license rule without separate permission. [Official model card](https://huggingface.co/facebook/mms-tts)
- Indic Parler-TTS officially supports Bengali and has Apache-2.0 weights, with approximately 0.9B parameters. Its official card now recommends the newer Indic-Speak model; treat either as a candidate for measured evaluation, not a free hosted endpoint. Downloading open weights does not remove inference compute costs. Do not present an unmeasured universal 8GB VRAM requirement as a fact. [Official model card](https://huggingface.co/ai4bharat/indic-parler-tts)
- Check the license and provenance of the **exact checkpoint**, training data restrictions, and bundled voice recording consent. A port's license label alone is insufficient evidence for an upstream model's rights.
- `edge-tts` is a third-party client for Microsoft Edge's online speech service; no API key is required by that client. The source repository provides no Microsoft production SLA or entitlement for a third-party app. The project's release history includes endpoint changes and audio failures. It is therefore an unsupported dependency risk rather than a dependable free production TTS API. This is an operational inference, not a legal conclusion about its permitted use. The existing device TTS proposal is safer. [Source repository](https://github.com/rany2/edge-tts), [Release history](https://github.com/rany2/edge-tts/releases)

## Deployment costs and constraints

| Component | Free path for demo/pilot | Production limit |
|---|---|---|
| Native build | Local Android toolchain and signed APK, or a cloud build within its free allowances | EAS is optional; free cloud quotas are not unlimited. Expo EAS `--local` officially supports Linux/macOS, not Windows; on Windows use Android Studio/native Gradle via Expo prebuild/local development, or a suitable Linux environment. [Local builds](https://docs.expo.dev/build-reference/local-builds/), [Local development](https://docs.expo.dev/guides/local-app-development/) |
| Android distribution | Direct APK for the pilot | Play Console requires US$25 once. Android's new outside-Play verification applies regionally from Sept 30, 2026, expanding globally later. Its free limited distribution account covers up to 20 devices; broad free sideloading should not be treated as an unconditional permanent strategy. Bangladesh is not named in the first four enforcement countries. [Play signup](https://support.google.com/googleplay/android-developer/answer/6112435), [Verification rollout and options](https://developer.android.com/developer-verification/guides) |
| iOS distribution | Local development is possible within Apple's restrictions; web fallback | Normal Apple Developer Program membership is US$99/year; do not promise a free App Store release. [Apple enrollment](https://developer.apple.com/help/account/membership/program-enrollment) |
| API hosting | Existing team hardware or bounded free hosting for demo | Render explicitly advises against production use of free instances. Free web services have limited resources and ephemeral files; uploaded disease photos cannot safely live on that filesystem. [Render free docs](https://render.com/docs/free), [Render resource explanation](https://render.com/articles/from-side-project-to-production-scaling-your-first-app) |
| PostgreSQL | Small free external database within quota | Render free PostgreSQL expires after 30 days and has no backups. Supabase free provides 500MB database capacity and can pause after inactivity. Maintain the existing SQLAlchemy/Alembic schema; an external hosted Postgres is infrastructure, not a reason to rewrite auth or business contracts. [Render](https://render.com/docs/free), [Supabase pricing](https://supabase.com/pricing), [Pause policy](https://supabase.com/kb/faqs/platform/free-project-pausing) |
| ML inference | Existing laptop/CPU and small traffic, measured separately from API | The repo has PyTorch/torchvision dependencies. Do not assume the combined API plus disease model fits a 512MB host. Measure cold start, resident RAM and inference latency. Split inference from the light API if necessary. Hugging Face's current docs say new Gradio/Docker compute Spaces require a paid plan; free personal accounts have a limited ZeroGPU Gradio exception, not a guaranteed free always-on FastAPI host. [HF Spaces](https://huggingface.co/docs/hub/spaces-overview) |
| Optional LLM | Restricted free API quota for experiments | Gemini free tier has model and rate limits and free-tier content may be used for product improvement. Use redacted synthetic data for demos where appropriate; avoid quietly submitting identifying farmer data. Deterministic evidence-backed Bangla answer templates are viable when the model is unavailable. [Pricing](https://ai.google.dev/gemini-api/docs/pricing), [Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits) |

## Release evidence to require

1. Install a signed release APK on actual low-end Android phones, including Android 10–12 and 13+, with denial, offline, missing Bangla voice/model, phone rotation/background and cold-start cases.
2. Run one real API-backed Bangla flow: select farm → ask today's action → hear short sourced advice → confirm action → see one saved task/problem → repeat/retry safely. Test cross-farm isolation and stale queued actions.
3. Report command success, misunderstood numbers/units, completion rate, median/p95 latency, peak RAM and actual monthly quota use. Never call speech support, disease accuracy, or crop recommendations production-validated from a browser-only demo.
4. Deploy with HTTPS, secrets outside APK/Git, schema migration instructions, independent media persistence, database backup/restore, request/upload limits, and explicit degraded modes when weather/AI services are down. Existing hardware or grants can cover expenses, but describe them as donated infrastructure rather than zero total operating cost.

## Plan status caveat

The plan's 2026-10-06 repository inventory is historical and must not be used as today's status: the inherited task context and current dependencies show auth, profiles, locations/resources, chat and modules have since been implemented. Reconcile the plan against current code before estimating effort. The plan also contains a multi-week, multi-region field study; that is a later validation program, not work a short hackathon implementation can truthfully claim completed.
