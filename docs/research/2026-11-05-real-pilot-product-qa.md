# Real pilot product decoding and QA

Research checked 2026-11-05 against the product owners' documentation. The IMERG file exists in `backend/data/earth_observation/raw/` and is recognized by the host `file` utility as HDF5. The host Python lacks h5py and this researcher could not access the Docker socket; the IMERG array observations below were supplied by a separate local inspection. MODIS and SRTM files were not found in that directory. Thus the structures and rules below are documented product expectations, not proof that the downloads are complete, authentic, spatially representative, or decodable. Inspect each actual granule before accepting it.

## IMERG Final daily V07B, 2024-01-01

The expected collection is [GPM_3IMERGDF V07](https://disc.gsfc.nasa.gov/datasets/GPM_3IMERGDF_07/summary?keywords=imerg), a global 0.1-degree daily NetCDF product. The documented variables include `precipitation` (combined microwave/IR daily mean rate, mm/day), `precipitation_cnt` (number of valid half-hourly precipitation retrievals), `precipitation_cnt_cond` (number at least 0.01 mm/hour), `MWprecipitation` and its corresponding counts, `randomError` (mm/day) and `randomError_cnt`, `probabilityLiquidPrecipitation` (percent), `lon`, `lat`, `time`, and `time_bnds`. A separate local inspection reports root-level `precipitation` and `precipitation_cnt` arrays with shape `(1, 3600, 1800)` and axes `(time, lon, lat)`; the count is int8, longitude float32, latitude float64, and a sampled count is 48. The inspected precipitation units attribute is the one-element array `["mm/day"]`; time units are `["days since 1980-01-06 00:00:00Z"]`. These observations do not establish coverage over either polygon. Inspect fill values, all relevant attributes and actual time bounds; do not assume an array axis order from the filename. Match 2024-01-01 using time bounds and granule metadata, and read coordinates rather than treating array indexes as geographic coordinates.

A daily rate is the mean of valid half-hourly rates multiplied by 24; zero rain is valid. A cell with zero valid observations is fill. Retain `precipitation_cnt` with the rate; report counts and incomplete temporal coverage (48 is a full day), and use `randomError` and its count if reporting uncertainty. A one-day rate can be expressed as a one-day equivalent in mm, but incomplete counts do not establish an observed full-day total. The valid sample count can reconstruct the simple partial-sample total as `precipitation * precipitation_cnt / 48` mm; it must not be mislabeled a full-day observed total. NASA warns of lower skill over frozen surfaces, complex terrain and coasts, and possible artifacts from changes in the constellation. The Final run is retrospective, not a live observation. [NASA GES DISC](https://disc.gsfc.nasa.gov/datasets/GPM_3IMERGDF_07/summary?keywords=imerg).

## MOD13Q1.061 h26v06

[NASA's collection record](https://doi.org/10.5067/MODIS/MOD13Q1.061) identifies HDF, sinusoidal tiles, nominal 250 m and 16-day composites. The named sample `MOD13Q1.A2023353.h26v06.061.2024005171256.hdf` begins on 2023 day 353 (December 19); the trailing timestamp is production time, not pixel observation time. A composite chooses a best available pixel from acquisitions in the period, not a daily mean. Use its per-pixel `250m 16 days composite day of the year` when associating observations with dates; check actual granule time bounds, including year boundaries.

Native SDS names and metadata documented by NASA:

| SDS | Native representation and interpretation |
| --- | --- |
| `250m 16 days NDVI`, `250m 16 days EVI` | int16; fill -3000; valid raw -2000..10000; scale 0.0001; dimensionless |
| `250m 16 days VI Quality` | uint16 bit field; fill 65535; valid 0..65534 |
| `250m 16 days pixel reliability` | int8; fill -1; ranks 0..3 |
| `250m 16 days composite day of the year` | int16; fill -1; valid 1..366 |

The file also contains red, NIR, blue and MIR reflectance and viewing/sun geometry layers. Mask raw fill and out-of-range NDVI before scaling. Retain both QA layers and observation day, and record the actual SDS dimensions, georeferencing, scale, fills and attributes from the HDF4 reader; HDF5 readers alone cannot be assumed to read HDF4. Use the sinusoidal metadata for reprojection, nearest-neighbor for categorical QA, and area-aware coverage/aggregation for AOIs. The filename identifies a tile, not proof it covers an entire polygon. [NASA product record](https://doi.org/10.5067/MODIS/MOD13Q1.061).

The [MODIS VI user guide](https://lpdaac.usgs.gov/documents/103/MOD13_User_Guide_V6.pdf) defines pixel reliability -1 as fill, 0 good, 1 marginal, 2 snow/ice and 3 cloudy. The detailed VI QA bit field encodes MODLAND quality (bits 0–1), VI usefulness (2–5), aerosol (6–7), adjacent cloud (8), atmospheric BRDF correction (9), mixed clouds (10), land/water (11–13), possible snow/ice (14) and shadow (15); use the guide's full code table, not an assumption that the entire word must be zero. Decode unsigned values only after excluding 65535. An initial conservative policy can require reliability 0 and MODLAND bits 0; record it as a project choice, not a NASA-mandated threshold. Report total AOI pixels, valid index pixels, QA-passing pixels, fractions and rejection reasons; avoid treating absent or cloudy pixels as zero vegetation. A sample tile and one composite cannot establish a time series.

## SRTMGL1 V003 HGT

The [SRTM collection guide](https://lpdaac.usgs.gov/documents/179/SRTM_User_Guide_V3.pdf) describes 1-arc-second, one-degree tiles as 3601 rows by 3601 columns of signed 16-bit big-endian integers, no header or trailer, north-to-south row-major order, elevations in meters. Adjacent edge rows/columns overlap; handle shared edges once during mosaicking. Geographic coordinates are sample posts, so use a reader that handles their spacing and origin correctly rather than treating 3601 posts as 3601 independent 1/3601-degree cells. For the named N24E088 and N22E091 tiles, the name specifies the southwest integer-degree corner; check actual members and extent. Vertical heights are referenced to EGM96 geoid; horizontal coordinates use WGS84, per the guide. Each uncompressed tile should contain 25,934,402 bytes (3601 × 3601 × 2); verify independently after extraction.

The guide states V3 is void-filled, while older V1/V2.1 mark voids -32768. Treat any -32768 present as missing rather than an elevation and flag it for review; don't infer full AOI coverage from a tile name or silently count missing values as elevation. V3 void filling can incorporate other source DEMs; elevations are a static terrain surface, not a current field measurement. Preserve tile provenance and report spatial coverage, missing fraction, resolution, datum, and resampling method. Read in binary big-endian (`>i2`), reshape 3601 × 3601 only after checking file size, or use a geospatial HGT reader and inspect its transform and nodata metadata. [NASA SRTM guide](https://lpdaac.usgs.gov/documents/179/SRTM_User_Guide_V3.pdf).

## Minimum evidence before pilot release

Record granule IDs, source URLs, timestamps, checksums, actual internal metadata and decoder versions; verify expected time/extent, variable names, dimensions, units, fill and quality layers from the files. Retain polygon definition and calculate spatial coverage and quality-passing fractions for each polygon and time. A filename, SHA-256 and container signature alone do not authenticate provenance or demonstrate meaningful coverage. No pilot coverage or numerical output has been verified in this note.
